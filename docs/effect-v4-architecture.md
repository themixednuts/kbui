# Effect v4 architecture

kbui uses Effect v4 as the owner of application work. Promise-, callback-, and
framework-shaped APIs exist only at the outside edge of an Effect program.

## Runtime boundaries

- Browser code uses the single `ManagedRuntime` in `src/lib/app/runtime.ts`.
- Worker, SvelteKit, Queue, Workflow, Durable Object, and Agent handlers use
  `runWorkerEffect` in `src/lib/effect/worker-runtime.ts` as their Promise bridge.
- Long-lived Svelte 5 programs are scoped through `effectAttachment` or
  `mountEffect`; Svelte signals mount/detach and Effect owns acquisition,
  fibers, retry, interruption, and release.
- Direct `Effect.runPromise` is forbidden outside the worker runtime bridge.
  Feature modules compose Effects and do not create private untracked runtimes.

## Failure policy

- Wire, storage, and third-party payloads are decoded before use.
- Permanent domain failures remain typed failures and are shown to the user.
- Transient infrastructure failures use an indefinitely jittered Effect
  schedule, scoped to the owning request/fiber. There is no polling or alternate
  data-source fallback.
- Cloudflare Queues own Queue retry. Workflows own durable step retry. The app
  does not acknowledge and manually re-enqueue the same message.
- Workflow steps use Cloudflare's current error-aware dynamic retry-delay API;
  rate-limit guidance and durable attempt context determine the next delay.
- Firmware generation is blocked when a keycode, behavior, target, key order,
  or binding cannot be represented exactly. It never substitutes a no-op key.

## Resource policy

- Browser workers, OPFS SQLite, WebHID reports, Web Serial, Web Bluetooth, ZMK
  RPC, WebSockets, streams, and event listeners are acquired/released by Effect
  or adapted by an interruptible `Effect.callback`.
- Cleanup errors are observed. Multi-resource cleanup attempts every release and
  aggregates failures.

## Cloudflare types and APIs

- `src/cloudflare.d.ts` is generated by `wrangler types`; application code does
  not import `cloudflare:workers` or depend on `@cloudflare/workers-types`.
- Queue, Workflow, Durable Object, and Agents SDK code uses the installed modern
  Cloudflare packages and generated binding types.
